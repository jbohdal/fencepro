# Billing & Ops Audit

## 1. Customer Record
- Interface: Customer (id, firstName, lastName, phone, email, serviceAddress, billingAddress, notes, tags[], salesRep)
- Tabs: overview, quotes, jobs, costing, files
- Storage: `fencepro_customers`
- No billing tab, no notes tab (notes is a single text field in overview)

## 2. Invoicing
- No standalone invoice system — invoicing is a Job field: invoiceNumber?, invoiceDate?, paymentStatus
- No invoice generation UI, no invoice documents, no line items
- Job status lifecycle includes `invoiced` and `paid` but no detail

## 3. Payments
- Job.paymentStatus: not_invoiced | invoiced | partial | paid
- Job.amountPaid: number, Job.paymentDate?, Job.paymentMethod?
- No dedicated payment recording UI — updated via job detail panel

## 4. Schedule Data Model
- ScheduledJob: id, clientName, area, sections, fenceType, jobPrice, tearout, crewId, date, notes, status
- No dollar-level breakdown per scheduled day

## 5. Operations Kanban (OperationsPage.tsx)
- Loads from jobStore + staging localStorage via buildUnifiedList()
- 12 columns (Awaiting Locates → Backorder)
- Card shows: name, type, sections, crew, date, value, advance button
- Issues: staging mapping can put jobs in wrong column, empty columns hidden, no milestones

## 6. Notes
- Customer.notes: single string field, textarea in overview tab
- Job.notes: single string field in job detail
- No rich text, no pinning, no multiple notes per entity

## 7. Pull Sheet System
- Pull sheet = SavedQuote.pullSheet: LineItem[] (item, qty, unitCost, total)
- Generated by materialCalculator.ts calculateMaterials()
- Stored embedded in quote object in fencepro_quotes
- Quote has optional customerId? field BUT it's never populated
- No link from customer record to pull sheets
- PO auto-created from pullSheet when materialsStatus → ordered
